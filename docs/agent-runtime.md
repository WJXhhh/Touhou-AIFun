# AIFun Agent 运行时 v1

本次改造仅修改 AIFun，保留实施前的未提交工作。基线副本位于 `build/agent-baseline-20261003-165241/`。没有修改 TLM 源码、公共 `ITool` 接口或现有聊天记忆格式，也没有引入外部 Agent 框架。

设计参考固定为 [Codex b741e480 的调度](https://github.com/openai/codex/blob/b741e480e203f037ca726bc2a76d99a8e8668e66/codex-rs/core/src/tools/parallel.rs)、[历史预算](https://github.com/openai/codex/blob/b741e480e203f037ca726bc2a76d99a8e8668e66/codex-rs/core/src/context_manager/history.rs)，以及 DSH `dd6322d604e00eec1ba5e0c8541159906a21094a` 的有界工具批次、按序提交和保留工具配对的压缩机制。

## 开关与使用

COMMON 配置 `[agentRuntimeV1]` 包含 `enabled=false` 和 `diagnostics=false`。运行时保持实验性、默认关闭：跨版本正确性回归与单项性能测试不能替代原计划要求的旧版/新版整体耗时验收。

开启后，每位女仆最多同时执行一个行动任务，另外容纳四个排队任务。正常聊天和问进度独立执行；新行动要求默认排队，明确“改做……”才替换，补充条件在行动边界生效。含糊要求由前台模型澄清。明确停止和停止按钮直接取消当前任务并暂停队列，清空队列需要明确请求。控制入口验证实际主人权限。

退出、主人离线、女仆卸载和关闭配置会暂停并保存检查点。重新进入后等待主人要求继续，先观察现场，再执行动作。不会恢复旧 GUI、旧 future、旧帧或旧观察作为动作凭据。GUI 操作预览显示当前任务、队列及暂停/继续/取消状态。

仅 AIFun 的 Chat Completions、Responses、ChatGPT 订阅、Anthropic 客户端接入新运行时；原版 TLM 客户端保留兼容路径。网络协议版本为 15，服务端与客户端需使用相同版本的 AIFun。

## 任务、事实和记录

`AgentExecution` 明确区分聊天、任务、知识提取、设置生成和辅助请求，并携带女仆、聊天轮次、任务及代际。任务使用独立 `TaskCallback`、消息历史和操作集合，前台聊天换轮不会丢弃后台结果。知识摘要子请求继承父执行的取消条件。

`AgentTaskState` 保存目标、约束版本、计划、当前步骤、阶段、证据引用、失败、Schema 加载集合和完成条件。状态包括 queued/running/waiting/paused/completed/failed/cancelled。`update_task_plan` 维护步骤；模型不能通过改计划覆盖真实执行事实。

独立的版本化女仆 NBT 保存任务与队列。世界 SavedData `touhou_aifun_agent_archive_v1.dat` 保存有界完整记录和原始结果，采用字节数组避免 NBT 字符串长度限制。记录包括模型步骤、调用、结果、取消和真实物品转移。归档有容量限制，活动记录无法继续保存时安全暂停。原始结果淘汰后保留摘要并明确报告引用失效，不重新执行原操作。

GUI 原子动作首先登记真实净转移，再提交模型结果。游标拾取不等于收货，实际落入女仆库存才登记；返还来源不重复计数，反向转移抵扣。GUI 关闭或卸载时的迟到游标结算进入世界归档，恢复时按事实版本与较旧实体检查点核对，避免重复搬运。

完成验证支持 transfer、inventory、position，以及最多 16 项原子条件的 all 组合。转移条件核对物品、维度、容器位置、方向和真实累计净数量；库存、位置条件读取当前服务器状态。补充数量后重新计算条件，现场未重新观察、条件缺失或未满足时不能凭模型文本标记成功。模型过早宣称完成时允许一次基于真实证据的纠正规划，仍不满足则暂停；不会自动重放世界修改。尚无领域验证器的开放任务保守暂停。

## 上下文与 Schema

完整归档与模型上下文分开。每轮提供当前用户约束、任务检查点、完成条件、相关事实、近期步骤及已加载工具。约 80% 消息预算触发精简，目标约 60%。先删除同一已结束批次的重复 GUI 快照，再按调用/结果完整组压缩。保留原始坐标、物品数量、真实动作、错误和未完成事项，保留未结束调用、最新批次和用户约束。

确定性精简仍无法容纳的旧自由文本才使用模型摘要，子请求可取消且不加载行动工具。精简后仍超预算会暂停，不发送明显超预算的请求。完整 GUI 首次结构留在当前工具结果，不再把同一套槽位重复塞入检查点。

`read_task_result` 按引用分页，每次含头部约 2,048 token；引用有上下文随机前缀，持久化后仍指向原结果。缓存同时有字符数、条目数及归档上限。

`load_tool_schema` 保留原入口，支持 `group:gui` 等工具组。Schema 在任务内持续加载，目录区分已加载/可发现工具，短目录与完整说明分开。注册表、技能定义和 `ToolSchemaDependencies` 声明的动态依赖变更会失效，执行前再次核对可用性。第三方可通过 AIFun 依赖声明接口提供版本，不需要改 TLM。

## 调度、扫描和工具成本

工具元数据描述线程、资源、并发、取消、结果预算和缓存。默认独占；已适配且独立的网络工具最多两个并行。GUI、背包、移动和未知第三方工具保持串行，世界访问仍在服务器 tick。每批最多 16 次调用，独立结果缓冲按调用顺序提交；取消后停止派发，已接受调用保留对应结果或取消记录。

操作集合覆盖原始模型 HTTP future、扫描、GUI、视觉和摘要。动作边界核对任务代际、目标版本和观察状态，状态不确定的世界修改不盲目重试。无进展检测结合库存、净转移、位置、阶段和有界状态历史，覆盖交替循环；两次提示重规划，继续无进展则暂停。

扫描新增可选 `intent=overview/locate/read_signs` 和 `detail=summary/full`。locate/read_signs 先查已加载区块候选并核对距离、方向、遮挡，避免先运行完整全景射线；原分帧扫描保留。多女仆共享每 tick 有界工作量，轮转调度，卸载及时取消。

缓存将几何观察与 focus 排序投影分离，检查姿态、开始/完成观察年龄、区块加载状态和区域版本。服务器方块更新使涉及区域失效，旧观察不会通过重置完成时间续期；告示牌读取重新获取文字。摘要返回重要目标坐标和未覆盖/省略说明，截断不能证明目标不存在。截图并行、主模型图片和回看能力保留。

容器发现优先已知目标及方块实体候选，非方块实体菜单保留有界回退搜索；候选接近位置用于导航，减少重复 BFS。支持明确的 `registry_id@x,y,z` 目标，仍检查坐标空间、冲突参数和实际方块类型。

GUI 首次返回完整槽位结构，后续默认只返回变化槽位、游标、数量和状态版本，关闭返回收尾结果。槽位说明区分主手、副手、背包，并给出背包索引。`gui_batch` 最多 16 个有序语义动作，每步校验，失败即停并报告部分成功，不提供事务回滚。兼容既有工具和无歧义的 `from_slot` 参数；冲突、非整数槽位、过期观察仍拒绝。未知协议和视觉动作不能绕过适配器、帧与布局校验。

知识/Wiki 约 2,048 token 内直接返回相关原文，较长资料才摘要；缓存按来源、内容、查询、语言、站点和模型区分。网页默认返回相关段落、必要链接和完整抓取引用。`query_game_context` 分类别计时和版本复用，位置及库存不长期缓存。

诊断只记录阶段、耗时、状态和体积，默认关闭；任务路径不输出含完整对话的请求 DEBUG 日志。阶段覆盖模型等待、排队、工具执行、导航、客户端回传、视觉和检查点。重叠阶段不能相加作为任务总耗时。

### 连续四箱实测与寻路修补

此前真实模型测试使用近处单箱、禁止普通 AI；双箱来源检查会传送女仆，未覆盖连续四箱行走。这是之前未发现本次卡顿的测试缺口。

新增专项夹具保留普通 AI，四箱相隔两格、箱旁有告示牌，女仆只在开始时设置位置，之后真实行走并转移物品。专项使用独立平地测试世界：旧 QA 世界的对应区域存在地下水，早期失败回放被地形污染，不能当作运行时失败或性能数据。

在干净夹具上，旧实现以 `.70` 方块偏移站立时稳定卡在第一箱外，真实距离约 2.256，超过 2.25 的交互半径，最终等待 400 tick。调查发现两处问题：BFS 可选择当前方块中心，中心在范围内不代表真实位置在范围内；即使选到相邻接近点，导航也可能返回终点已在交互范围内、但 `canReach=false` 的路径，工具将它丢弃而不移动。

现在排除范围外的当前方块作为接近点；对于返回的路径，以终点是否在箱子交互范围内判定可使用的部分路径。所有节点仍受活动范围限制，真正打开容器前仍检查真实距离。没有扩大交互距离、延长等待上限或自动重试物品操作。

## 2026-10-05 请求前缀与 token 缓存治理

发现 Anthropic 适配器会把所有 SYSTEM 消息提升到顶层 system，包括逐轮变化的任务检查点、game_tick、完成数量、现场证据和前台任务状态。它们位于工具历史之前，改变进度会改变整段历史共同前缀。DeepSeek 的缓存依赖已经落盘的匹配前缀，默认开启；Anthropic 兼容接口忽略 cache_control，所以没有增加一个无效的缓存开关。依据：[DeepSeek 缓存规则](https://api-docs.deepseek.com/guides/kv_cache/)、[Anthropic 兼容详情](https://api-docs.deepseek.com/guides/anthropic_api/)。

受管理的 Anthropic 请求只把开头的稳定系统规则放在顶层 system；后续运行时消息、当前检查点、已加载工具列表和情绪提醒放到全部 tool_result 之后的运行时上下文。固定系统规则说明这些状态和必要步骤的含义，观察依然是数据。所有工具结果仍有原 call id，并保持成组、按序提交。旧检查点继续被替换，不积累重复状态。辅助知识提取和设置生成维持原系统消息兼容路径。实际动作权限、现场验证和任务完成检查均未放宽。

把容器范围、完成条件和最终 GUI 操作指导移到任务创建时的一次性固定系统规则，检查点只重复简短下一步提醒。工具目录与可选 Schema 按工具 id 排序，已加载列表排序；实际增加工具或动态定义变化仍会正常改变请求，不为了缓存维持失效定义。OpenAI Chat Completions、Responses 和 ChatGPT 订阅原先已经保持系统消息的序列位置，这次共用稳定规则和工具排序。
