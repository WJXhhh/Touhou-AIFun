# 女仆拔刀剑战斗 AI 设计与验证

日期：2026-10-24。主要目标为 Minecraft 1.20.1 Forge、拔刀剑重锋 CR1.13，同时考虑 CR 后续版本与上游重锋新版。

建议做成能判断距离、威胁和连段机会的高手型战斗 AI：近身持续压制，受威胁时规避，抓住机会蓄力或追击；技能范围和伤害仍由手中的刀决定。战斗反应在服务端运行，LLM 负责接收主人命令和调整策略。

方案已获用户确认，剑技执行现已实现。实现使用当前主手刀的原生连段与 SA，并在每 tick 和施放前重新检查力量附魔、SA、刀实例、连段根节点及断刀和封印状态；换刀或原地修改这些能力会取消旧蓄力并移除旧攻击实体。

## 当前实现

`SlashBladeCombat` 负责服务端动作时钟、按战况选招与攻击实体代际；`SlashBladeTactics` 负责本体八种 SA 的保守分类。兼容层通过启动时读取实际 jar 的类与方法描述符选择能力，CR 伤害倍率修正按实际方法体识别，未安装拔刀剑时不加载可选剑技类。

已接入地面 A/B/C、强化分支、迅冲斩、上斩与升空衔接、空中连击、空坠斩、普通和完美 SA、四种幻剑阵、即时格挡、瞬步规避、受阻时上行与有条件的隔空追击。Super SA 单独开关，默认关闭。借力跳、踢跃、独立的瞬步退行和女仆身体 VMD 动画尚未加入；普通寻路与安全落地检查承担相应基础移动。

普通 SA 通过原生 `releaseUsing` 释放并扣费。每把刀只使用自己登记的 SA，未知附属 SA 不自动释放。幻影剑和幻剑阵必须有当前主手刀的力量附魔，力量药水效果不能替代。

配置位于 `touhou-aifun.toml` 的 `[combat]`：

| 配置 | 默认 | 作用 |
| --- | --- | --- |
| `slashbladeAI` | `true` | 开启拔刀剑战斗接管；仍受现有战斗模式和目标规则约束 |
| `slashbladePhantomSwords` | `true` | 在武器、附魔和耀魂条件满足时使用幻影剑与剑阵 |
| `slashbladeSuperSA` | `false` | 允许原生条件下的 Super SA，消耗最大耐久的一半 |

刀光、剑气、次元斩、幻影剑与反弹的普通箭均纳入目标保护和攻击追踪；停止、更换武器、更换 SA 或力量等级后，旧攻击实体会被清理。同一世界 tick 的主手物品更新有防重门控。网络使用原生装备同步和攻击实体同步，未增加 AIFun 消息格式。

当前仅使用刀上已有的耀魂，并保留原生 SA 的耐久替代规则；女仆击杀转耀魂兼容暂未加入。客户端持刀动画、不同身体模型及光影观感需要实机检查，不将服务端技能测试视为动画验收。

以下名称按 CR1.13 语言文件和实际代码核对。右栏是拟采用的战术用途。

| 类别 | 技能或分支 | 条件与用途 |
| --- | --- | --- |

| 地面连击 | 连击 B、连击 C | 通过不同停顿进入分支；按目标是否稳定、周围是否危险选择长短连段 |

| 射技 | 怒风幻剑阵 | 围绕锁定目标展开，适合控制与衔接追击 |
| 射技 | 急袭幻剑阵 | 展开后快速攻击，适合锁定重点目标施压 |
| 射技 | 暴雨幻剑阵，常称五月雨 | 从目标上方攻击；用于聚集、移动受限的敌人，限制同时存在数量 |
| 防御 | 防御、即时格挡 | 要求未断刀、荆棘附魔、落地和正面条件；普通防御主要挡远程，即时格挡可挡相应近战 |

| 机动 | 隔空瞬步 | 锁定追击；落点需有空间、在活动范围内，且不借此穿越阻挡视线的墙壁 |
| 机动 | 瞬步上行、瞬步退行 | 调整高度和脱离空中危险；不作为持续无敌循环 |
| 空中辅助 | 借力跳、踢跃 | 二期增强项，用于有限续空与脱困，限制连续次数 |
| 终极技 | Super SA | 独立开关，建议默认关闭；启用后仍遵守原生武器条件与耐久代价 |

SA 是刀携带的能力，不是所有女仆固定拥有的技能池。CR1.13 注册了以下八种有效 SA：

| SA | 拟定使用场景 |
| --- | --- |
| 次元斩 | 对锁定目标施压，接近困难或追击时使用；额外检查视线与活动距离 |
| 终焉樱 | 近身多段爆发，目标进入有效范围且有施展空间时使用 |
| 虚无刀界 | 目标稳定、周围安全时投入较长动作，避免对快速离开的目标空放 |
| 円刃 | 周围多个有效敌人时优先考虑 |
| 幻影刃 | 前方有目标与清晰射线时使用横向飞行剑气 |
| 幻影刃 纵 | 前方有目标与清晰射线时使用纵向飞行剑气 |
| 波刀龙胆 | 沿前方释放攻击，应对目标聚集的方向 |
| 平突 | 目标位于可通行的前方，适合直线接近与突刺 |

这份分类是战术用途，不对未知附属 SA 推断伤害、射程或安全性。认识的注册键配对应策略；未知 SA 默认关闭自动释放，仍可使用已验证的基础连段。后续通过独立技能描述适配附属。

### 原生限制

- CR1.13 的普通 SA 基础蓄力为 9 tick，完美窗口基础为 3 tick，并受灵魂疾行影响。执行时读取接口，避免把基础值写死到调度器。
- SA 的默认耀魂消耗为 20，实际读取当前 SA 的费用；不足时原生释放路径可消耗 1 耐久。建议普通敌人优先保留耐久，紧急护主或高价值目标才允许耐久替代，并设下限。
- 幻影剑要求妖刀、力量附魔、未封印、未断刀；单发与剑阵费用从重锋配置读取，默认分别为 2、20。附魔决定相应伤害，评级影响部分剑阵数量。
- 即时格挡窗口基础为 5 tick，加灵魂疾行等级；成功后有原生短暂无敌。AI 不在收到伤害事件时临时重置输入时间，也不反复开关潜行维持完美窗口。
- Super SA 要求妖刀、千杀条件、未封印、未断刀、零损伤与落地，并消耗最大耐久的一半。不能把它做成普通循环技能。

## 拟定战斗行为

### 每次行动的选择

服务端每 tick 推进当前动作与紧急威胁检查，低频更新附近敌人和地形缓存。候选动作先通过武器、资源、目标、地形和当前动作窗口检查，再按护主紧迫性、预计命中机会、暴露风险和资源成本排序。

一个动作开始后保持到合法衔接点，防止每 tick 改主意而反复起手。目标死亡、主人叫停或硬规则拒绝时立即撤销后续攻击，并处理已生成攻击实体的停止与失效。

| 战况 | 优先行为 |
| --- | --- |
| 普通近战敌人 | 进入当前刀的有效距离，短连段确认位置，再接 A 或 C；敌人稳定且没有侧面威胁时才打长 B |
| 正前方目标稍远 | 有安全通道则迅冲斩接近；距离仍很远则正常寻路，条件允许时用幻影剑压制 |
| 骷髅或其他远程敌人 | 观察实际弹道侧闪，缩短直线暴露时间，再突进；存在合适锁定与落点时才用隔空瞬步 |
| 多个敌人贴身 | 调整角度减少被包围，按手中 SA 选择群攻；不会在没有对应 SA 的刀上调用円刃 |
| 轻型敌人被挑起 | 确认击飞与高度后接跃升或空连，最后空坠斩落地；不为表演反复升空 |
| Boss 或无法击飞的目标 | 识别实际抗击退表现，减少挑空，改用地面连击、合适 SA 和攻防换位 |
| 女仆血量低或侧面威胁大 | 终止贪长连段，优先规避、拉开后再进场；保留护主所需距离 |
| 主人正在受威胁 | 复用现有护主优先级，选择能及时干预的目标与动作；不为打完旧连段延误接敌 |
| 无视线、目标出界或追击失败 | 停止远程空放，尝试有限寻路或脱战，避免隔墙无限次元斩与跨区域追杀 |
| 耀魂不足或刀濒临断裂 | 降低耗资源动作频率，基础连段继续按武器实际能力运行 |

例如对单个僵尸，可以是“接近 → A 起手 → 上斩 → 确认击飞 → 跃升空连 → 安全落地”；面对Boss则可能是“侧闪 → 短连段 → 趁空档蓄力本刀 SA → 换位”。这些是可选路线，实际每次都以命中、敌人状态和合法衔接窗口决定。

### 强度与反应

建议默认高手档：衔接熟练、会完美蓄力、会使用已有的幻影剑与规避能力。防御反应依据视线内的弹道、挥击、接近趋势和已知伤害来源，不能对没有外部信号的所有模组攻击保证提前躲避。

原生回避次数与时间窗继续生效，并增加共享防御调度，避免格挡、跳跃无敌和瞬步轮流维持全程无敌。移动必须有实际战术价值；威胁不大时优先完成进攻。具体反应时间、规避频率和长连段倾向在实机对照后校准，文档不把未测数值当作平衡结论。

## 与现有战斗系统衔接

1. **统一攻击控制。** 沿用 `MaidCombatReflex` 的护主、命令、自卫目标优先级；普通攻击工作模式产生的合法 `ATTACK_TARGET` 也能交给拔刀 AI。武器执行期间，本模组普通近战、普通追击及基模对应攻击行为需要互斥。
2. **替换简单刀光适配。** TLM 1.5.3 的 `SlashBladeCompat.swingSlashBlade` 在攻击工作模式下生成随机角度刀光并重置 `lastActionTime`。拔刀 AI 接管时应屏蔽这一次简单刀光，避免动作重置和额外伤害。
3. **建立唯一动作时钟。** 重锋主要通过 `ItemSlashBlade.inventoryTick` 推进连段时间轴与输入调度。女仆不是玩家背包，必须明确手持刀的 tick 入口；同一把刀每个世界 tick 最多推进一次。不能同时手动推进与调用完整物品 tick，造成双重命中。
4. **覆盖独立伤害路径。** 重锋刀光、次元斩与幻影剑有直接伤害路径，不能只依赖 `MaidHurtTarget.Pre`。需在选取目标和结算伤害时识别女仆来源，复用主人保护、玩家门控、公共女仆、宠物、NPC、女仆、`MaidNoAttack` 与清仇恨抑制规则；控制和击退也应在拒绝目标前拦截。
5. **资源不伪造。** CR1.13 的击杀数接受 `LivingEntity`，但经验转耀魂只走 `getAttackingPlayer()`，女仆没有等价原生入口。首阶段使用刀上已有耀魂；建议增加可配置的女仆击杀转耀魂兼容，按有效击杀与经验等价值设上限、去重归因，避免无成本自动回魂。
6. **表现单独验收。** 原生刀光实体可复用，但 TLM 现有持刀渲染只做简单动作效果。真实连段伤害成立不代表女仆身体模型自动拥有玩家 VMD 动作。先验收刀光、朝向与持刀表现，再决定身体动画增强；多人旁观者必须看到一致动作。

停战与更换武器时清理虚拟输入、蓄力、锁定、导航占用、待发技能和本次战斗跟踪的攻击实体；旧技能不能在换刀后继续借新刀的属性造成伤害。死亡、卸载与退出世界同样释放状态。

## 新版兼容设计

战术层只处理“接近、连击、蓄力、射击、规避、撤出”这些动作意图。重锋的类型、方法、注册表和输入细节集中在可选兼容模块，未安装时不加载这些类。

### 复用共同接口

此次对照中，`progressCombo(LivingEntity)`、`doChargeAction(LivingEntity,int)`、连段查询、锁定目标和输入状态等主要入口仍然存在。普通连段尊重刀的 `getComboRoot()` 与实际 `getNext()`；蓄力走刀自身的释放路径和收费逻辑，不能只调用 `doChargeAction` 后忘记扣费。

幻影剑和瞬步的玩家输入事件仍以 `ServerPlayer` 为主体。女仆适配应复用原生实体、能力状态和费用规则，为非玩家补执行桥接；不制造 FakePlayer、不伪造玩家网络输入，也不复制整套伤害公式。

### 已确认的接口差异

| 差异 | CR1.13 | 上游 1.9.65 | 处理方式 |
| --- | --- | --- | --- |
| `InputCommandEvent` 包路径 | `event` | `event.handler` | 不把玩家输入事件作为女仆执行核心 |
| `getSpecialEffects()` 返回类型 | `List` | `Collection` | 不从公共战术层直接链接变化的方法描述符 |
| `setProudSoulCost(int)` 返回类型 | `void` | `SlashArts` | AI 读取费用，不修改注册 SA 的费用 |
| 主手检查 | `inventoryTick` 内主要使用 `isSelected` | 增加 `isInMainhand` 检查 | 桥接始终传女仆实际主手，避免背包刀也推进攻击 |

相同 `mod_id=slashblade` 和相近的 Java 方法名不能证明二进制兼容。实现时优先链接稳定子集，差异只放在少量版本桥接中；需要反射的入口启动时解析并缓存，不在每 tick 扫描。按实际类、方法描述符和能力检测选择支持范围，并记录一次诊断。

未知后续版本只有在目标过滤、伤害归因和 tick 互斥等共同基础被确认时才启用对应能力；缺少可选射技时可降级为已验证的连段。若连基础安全接口都不匹配，则关闭本附属的拔刀接管并明确日志，不能带着部分失效的保护继续施放。

## 实现顺序与验收

用户审阅通过后，建议按以下顺序推进：

1. 先做 CR1.13、CR1.15、上游 1.9.65 的可选加载、动作时钟、原有行为互斥、全伤害路径保护与停战清理。
2. 实现地面 A/B/C、迅冲斩、普通与完美 SA、基础幻影剑、战术走位和有节制的瞬步回避，形成可实机验收的主战版本。
3. 加入挑空确认、御空刀舞、星旋天翔、空坠斩、四种幻剑阵、隔空瞬步与防御格挡，完善完整战斗风格。
4. 视实机结果增加借力跳、踢跃、身体动画和可选 Super SA。

| 验收项 | 通过条件 |
| --- | --- |
| 版本矩阵 | CR1.13、CR1.14、CR1.15、上游 1.9.65 分别独立运行；不把同 mod_id 的不同版本装在一起 |
| 可选依赖 | 未安装重锋时客户端和专用服务端正常加载 |
| 连段正确性 | 命中时序与原生窗口一致，同一 tick 无重复推进、无额外普通刀光和普攻叠加 |
| 武器差异 | 不同 SA 的刀产生对应技能；无附魔、封印、断刀、缺少力量附魔时不越过原生条件 |
| 目标保护 | 主人、受保护玩家、宠物、NPC 和被清仇恨目标不受直接、飞行、持续攻击及附加控制影响 |
